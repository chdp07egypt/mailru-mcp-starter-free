# Безопасность и границы примера

Это независимый пример личной интеграции, не аудитированный многопользовательский OAuth-провайдер. Каждый владелец разворачивает свой сервер и использует свои Google OAuth credentials и пароль внешнего приложения Mail.ru.

## Секреты

В исходниках нет рабочих паролей, токенов, личных адресов и готового endpoint автора. `.env.example` содержит пустые секретные поля. `.gitignore` исключает реальные `.env`, ключи, журналы и экспорт писем. Скрипт `scripts/check_public.py` ищет известные форматы credential и запрещённые артефакты, но не гарантирует обнаружение всех секретов.

Не добавляйте настоящие переменные в GitHub Actions secrets для тестов: тесты полностью локальные, с подменами. Не прикладывайте настройки, email bodies или OAuth URLs с `code` к issues. Если обнаружен секрет, отзовите его у провайдера прежде, чем исправлять публичную историю.

## Авторизация

- Единственный `mail.access` явно покрывает поиск, чтение, перемещение и корзину.
- Принять можно только подтверждённый Google email владельца; по желанию фиксируется Google `sub`.
- Google ID token проверяется по RS256/JWKS, issuer, audience, срокам и nonce. Google access/ID tokens не передаются в ChatGPT как почтовые credentials.
- MCP access token проверяется отдельно: HS256, фиксированный issuer/audience, срок, owner и scope. Refresh token не подходит как bearer для `/mcp`.
- Authorization Code с S256 PKCE; одноразовые короткие коды, привязка flow к защищённой cookie, CSRF и Origin-проверка формы.
- DCR принимает только разрешённые callback-пути на `chatgpt.com`/`chat.openai.com`. Запросы по произвольным callback URL не выполняются.
- Статический bearer `MCP_ACCESS_TOKEN` остаётся для локальных клиентов; он даёт полный доступ к реализованным командам. Не вставлять его в браузерный URL.

Персональные исключения для старых токенов в эту версию не включены. Для изменения модели прав потребуется отдельное решение; текущие read-only credentials нельзя считать согласованными на запись.

## Работа с письмами

TLS проверяется штатной библиотекой. IMAP-хост фиксирован. Все значения команд экранируются, CR/LF запрещены. Для изменения принимается только один положительный 32-битный UID, проверяется UIDVALIDITY. Корзина определяется по специальному флагу `\\Trash`, а не по предположению о языке её имени.

`UID MOVE` переносит выбранное письмо. Приложение не вызывает общий `EXPUNGE`, не очищает корзину и не реализует безвозвратное удаление. При неопределённом результате требуется сверить обе папки до повтора.

Внешние ссылки и картинки не загружаются. Содержимое письма, включая просьбы агента «выполнить команду», — недоверенные данные. Запись в почту допустима по поручению пользователя, а не по инструкциям из письма.

## Данные и ограничения

Выбранные заголовки и тела обрабатываются на вашем Render и передаются MCP-клиенту ChatGPT. Почтовый пароль хранится в Environment Render. Это не локальная обработка и не сквозное шифрование от Render/ChatGPT.

Flow/code хранятся в памяти одного процесса, без распределённого state store. Refresh tokens не имеют индивидуального отзыва и отслеживания повторного использования. Для общего production-сервиса нужны стандартный OAuth-провайдер/постоянное хранилище, управление сессиями, лимиты и отдельный аудит.

Не сообщайте о возможной уязвимости публично вместе с паролями или персональными данными. До настройки приватного канала связи публичное issue должно содержать только обезличенное описание проблемы и способ безопасно воспроизвести её на тестовых данных.
