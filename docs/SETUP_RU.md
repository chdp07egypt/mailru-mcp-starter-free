# Как подключить свой Mail.ru к ChatGPT

Инструкция для личного сервера одного владельца. Сначала подготовьте свой ящик, затем хостинг и Google OAuth, после этого подключайте ChatGPT. Имена пунктов интерфейсов могут отличаться; ссылки на первоисточники находятся в конце.

## 0. Что понадобится

- Аккаунт Mail.ru с доступом по IMAP.
- **Отдельный пароль для внешнего приложения Mail.ru.** Основной пароль ящика не подходит.
- GitHub и Fork этого репозитория.
- Render с доступом к Fork.
- Google-аккаунт и собственный проект Google Cloud.
- ChatGPT на вебе с доступным пунктом добавления custom MCP server. Доступ зависит от аккаунта и политики workspace; не обещается для любого тарифа.

Не передавайте пароль ящика, пароль приложения, Google client secret или bearer token собеседнику в чате. Они вводятся только в защищённые настройки соответствующего сервиса.

## 1. Mail.ru: обязательный пароль внешнего приложения

1. Откройте свою почту в браузере.
2. Перейдите: **Настройки → Все настройки → Безопасность → Пароли для внешних приложений**.
3. Нажмите **Создать**, задайте понятное имя, например `personal-mail-mcp`.
4. Выберите **«Полный доступ к Почте»** и продолжите создание.
5. Сохраните выданный пароль в своём менеджере паролей. Далее он используется как `MAILRU_APP_PASSWORD`.
6. В разделе внешних сервисов проверьте, что доступ к ящику по IMAP разрешён.

Для входа используйте **полный адрес**, например `your-mailbox@mail.ru`. Соединение: `imap.mail.ru`, **993**, **SSL/TLS**. Сервер в коде фиксирован, проверка сертификата включена. Не подменяйте его произвольным хостом и не отключайте TLS-проверку.

SMTP `smtp.mail.ru:465` нужен почтовым клиентам для отправки. В этом проекте отправки нет, поэтому SMTP не настраивается.

Официальный источник: [вход Mail.ru в стороннюю почтовую программу](https://help.mail.ru/mail/login/mailer/).

## 2. GitHub: собственная копия

Нажмите **Fork** в этом репозитории. Достаточно публичной копии: секреты в неё не попадают, если следовать инструкции. Проверьте, что в вашем Fork нет `.env`, экспортов писем, скриншотов настроек и настоящих значений в примерах.

Рабочие файлы: `server.py`, `oauth.py`, `mailbox_client.py`, `requirements.txt`, `render.yaml`. Не включайте в репозиторий свою почтовую базу или историю личного чата.

Для локальной работы после Fork:

```bash
git clone https://github.com/YOUR_LOGIN/mailru-mcp-starter-free.git
cd mailru-mcp-starter-free
```

Замените `YOUR_LOGIN` на свой GitHub login. Создание venv и тесты описаны в README.

## 3. Render: создать сервис

### Вариант A — Blueprint

1. В Render создайте новый **Blueprint** из своего Fork.
2. Render прочитает `render.yaml`. Убедитесь, что план сервиса — **Free**.
3. Введите запрошенные почтовые переменные. Blueprint намеренно не требует Google credentials до получения адреса сервиса. Добавьте их вручную в Environment по шагам 4–5. До этого Google-вход ожидаемо отвечает, что OAuth не настроен.
4. Дождитесь окончания развёртывания. Запишите HTTPS origin, например `https://YOUR-SERVICE.onrender.com`.

### Вариант B — Web Service вручную

Если Blueprint неудобен, создайте **New → Web Service** из Fork и задайте:

| Поле | Значение |
|---|---|
| Runtime | Python |
| Root Directory | Пусто — файлы находятся в корне |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `uvicorn server:app --host 0.0.0.0 --port $PORT --no-access-log` |
| Health Check Path | `/healthz` |
| Instance Type | Free |
| Environment | Переменные из шага 5 |

Если интерфейс предлагает авторизовать GitHub, дайте Render доступ к своему Fork. Создание GitHub-репозитория само по себе не означает, что Render уже получил к нему доступ.

## 4. Google OAuth: идентификация владельца

Это отдельная настройка. Вход Google в Render **не создаёт** OAuth Client для вашего MCP.

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) и создайте/выберите собственный проект.
2. В Google Auth Platform / APIs & Services настройте Branding, Audience и OAuth consent screen. Укажите имя приложения и свой контактный email.
3. Для личного эксперимента можно оставить приложение в Testing. Добавьте **свой Google email в Test users**, если используется внешняя аудитория.
4. В Clients / Credentials создайте OAuth client типа **Web application**.
5. В **Authorized redirect URIs** укажите ровно:

   ```text
   https://YOUR-SERVICE.onrender.com/oauth/google/callback
   ```

6. Сохраните **Client ID** и **Client secret** в Render Environment, не в GitHub.

`YOUR-SERVICE` заменяется настоящим именем вашего Render-сервиса. `/mcp` и callback ChatGPT сюда не подходят. Если сменился домен сервера, нужно обновить Google redirect URI и переподключить MCP.

Upstream-запрос к Google использует только **`openid email`**. Gmail API, доступ к Google Drive и почтовому ящику Gmail не нужны. Google email владельца и адрес Mail.ru могут различаться.

## 5. Render Environment: значения

| Ключ | Что вводить |
|---|---|
| `PYTHON_VERSION` | `3.12.10` — проверенная версия, также указана в Blueprint |
| `MAILRU_USER` | Полный адрес своего Mail.ru ящика |
| `MAILRU_APP_PASSWORD` | Пароль **внешнего приложения** из шага 1 |
| `MCP_ACCESS_TOKEN` | Случайная строка длиной минимум 32 символа. Blueprint генерирует автоматически |
| `GOOGLE_CLIENT_ID` | Client ID из шага 4 |
| `GOOGLE_CLIENT_SECRET` | Секрет того же клиента |
| `ALLOWED_GOOGLE_EMAIL` | Точный Google email, которым будете входить в MCP |

Для ручной генерации ключа локально:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Скопируйте результат прямо в Render и свой менеджер паролей. Не отправляйте его в чат. Этот ключ одновременно защищает локальных bearer-клиентов и служит материалом для отдельного ключа подписи OAuth-токенов. Его смена отзывает токены и DCR-регистрации.

**Необязательные переменные:**

- `PUBLIC_BASE_URL`: только HTTPS origin без пути, query и credentials. На обычном Render не нужен: используется `RENDER_EXTERNAL_HOSTNAME`, выставленный платформой. Для кастомного домена задайте origin явно.
- `ALLOWED_GOOGLE_SUB`: дополнительная проверка неизменяемого Google subject; оставьте незаданным, если не настраиваете её осознанно.

Сохраните Environment с новым deploy. `/healthz` должен вернуть `{"status":"ok","version":"1.0.0"}`. Это подтверждает процесс HTTP, **не проверяет пароль Mail.ru**.

## 6. ChatGPT: создать настоящий MCP-плагин

1. Откройте **Plugins / Плагины** на вебе ChatGPT.
2. Нажмите **«+» / «Добавить» → Add custom MCP server / Добавить пользовательский сервер MCP**.
3. Имя, например `My Mail.ru`; Server URL:

   ```text
   https://YOUR-SERVICE.onrender.com/mcp
   ```

4. Выберите **OAuth**, регистрацию клиента **DCR / Dynamic client registration**. Если доступно поле scope, укажите **`mail.access`**.
5. Endpoints должны определиться из metadata. Если форма требует явного ввода:

   | Поле | URL |
   |---|---|
   | Authorization | `https://YOUR-SERVICE.onrender.com/oauth/authorize` |
   | Token | `https://YOUR-SERVICE.onrender.com/oauth/token` |
   | Registration | `https://YOUR-SERVICE.onrender.com/oauth/register` |
   | Resource | `https://YOUR-SERVICE.onrender.com/mcp` |

6. Прочитайте предупреждение о доступе сервера к почтовым данным и создайте/установите личный плагин.
7. Нажмите «Подключить», выберите разрешённый Google-аккаунт и подтвердите страницу сервера, где перечислены **поиск, чтение, перемещение и удаление в корзину**.
8. Откройте «Попробовать в чате» или выберите плагин через `@`. Должны быть **3 Read** и **2 Write** инструмента.

Простой загруженный skill/ZIP с инструкцией — ещё не доказательство подключения MCP. Проверяйте наличие именно пяти команд. [examples/mcp.json](../examples/mcp.json) — образец для клиентов/пакетов, поддерживающих эту OAuth-конфигурацию; сам по себе файл не подключает ChatGPT и содержит только заглушки.

### Три разных разрешения

- **Пароль приложения Mail.ru** разрешает серверу IMAP-доступ к ящику.
- **OAuth `mail.access`** разрешает выбранному Google-пользователю обращаться к вашему MCP.
- **Разрешения плагина в ChatGPT** управляют подтверждением вызовов. Они не заменяют пароль или OAuth scope.

Публичный шаблон запрашивает единый scope с первого подключения. Токены старой персональной версии `mail.read`/`mail.modify` не подходят. При переходе со старого сервера используйте отдельное подключение/регистрацию и новые секреты; не переносите старые токены и персональные исключения.

## 7. Проверка результата

Сначала отправьте себе отдельное безобидное письмо с уникальной темой, например `MCP-CHECK-2026-DEMO`. Убедитесь, что оно находится во «Входящих» и непрочитано. Не используйте для первого опыта документы или важную переписку.

Дайте ChatGPT последовательные поручения:

1. «Через My Mail.ru покажи папки» — проверка реального IMAP-входа.
2. «Найди письмо с темой MCP-CHECK-2026-DEMO» — заголовок с UID и UIDVALIDITY.
3. «Прочитай это письмо» — текст получен, отметка непрочитанного сохранена.
4. «Перемести это письмо в корзину» — `status: moved`, источник больше не содержит UID.
5. «Найди письмо в корзине» — подтверждение назначения; UID после перемещения изменяется.
6. «Верни это письмо из корзины во Входящие» — повторный поиск в корзине и `mail_move` с новым UID и её UIDVALIDITY.

Для каждой записи используйте **свежие идентификаторы из поиска соответствующей папки**. Код принимает только один UID, не диапазон. Название русской папки из `mail_list_folders` передаётся в серверном modified UTF-7; его не нужно переводить вручную.

После `unknown`/`not_confirmed` **не повторяйте MOVE вслепую**: проверьте обе папки. Соединение могло оборваться уже после выполнения операции.

## 8. Частые проблемы

| Симптом | Что проверить |
|---|---|
| `Mail connection failed` | Полный адрес, включённый IMAP, **пароль внешнего приложения**, тип «Полный доступ к Почте», завершённый redeploy Environment |
| `/healthz` работает, письма не читаются | Health не выполняет IMAP login; вызовите `mail_list_folders` |
| `Google OAuth is not configured` | Три Google-переменные в Environment |
| `redirect_uri_mismatch` | Совпадение Google callback до последнего символа, включая домен |
| Аккаунт не разрешён | Test users и точное значение `ALLOWED_GOOGLE_EMAIL` |
| `invalid_origin` | Обновлённый исходник с `Referrer-Policy: same-origin`; начать подключение заново |
| `invalid_consent` после deploy | Состояние входа было в памяти старого процесса; начать OAuth заново, не перезагружать старый callback |
| После согласия нет возврата в ChatGPT | CSP должен разрешать валидированные ChatGPT callback; используйте код из репозитория |
| Есть skill, но нет MCP-команд | Создать custom MCP server, установить его, проверить 3 Read + 2 Write |
| Новых команд нет | Settings приложения → «Обновить инструменты»; новый чат/повторный выбор плагина, если текущий чат сохранил старый набор |
| Нужны дополнительные scopes | В этой версии единственный scope `mail.access`; не используйте настройки старой версии; создайте свежее OAuth-подключение |
| Сервер долго отвечает после простоя | Render Free просыпается примерно минуту; открыть `/healthz`, дождаться ответа и повторить чтение один раз |
| `Folder changed` | Повторить поиск: UIDVALIDITY не совпадает |
| Нет `MOVE` | Запись не выполняется; небезопасного общего `EXPUNGE` в качестве обхода нет |
| Нет пункта custom MCP | Проверить доступность функции и политики аккаунта/workspace; код сервера этого не меняет |

Логи используйте без токенов, паролей и текстов писем. В Uvicorn отключён access log, чтобы OAuth callback с code не попадал в стандартные журналы приложения. Проверьте отдельно настройки логирования прокси/платформы.

## 9. Обновления и отзыв доступа

Обновляйте свой Fork и дожидайтесь завершения deploy. Изменились команды/metadata — обновите инструменты плагина в ChatGPT. Для отзыва IMAP-доступа удалите соответствующий пароль внешнего приложения в Mail.ru. Для отзыва MCP-токенов смените `MCP_ACCESS_TOKEN`, redeploy и подключите свой плагин заново.

Не переносите переменные Environment или историю рабочего приватного репозитория в публичный Fork. Если секрет уже был опубликован, удаление строки недостаточно: сначала отозвать/сменить секрет, затем разбирать историю.

## 10. Ограничения и первоисточники

Доступны до 30 заголовков за поиск, до 2 MB исходного письма и 40 000 символов тела. Пагинации, вложений, создания папок и фильтров нет. Поиск отсортирован по убыванию UID, а не гарантированно по дате заголовка. HTML возвращается как данные, не исполняется.

Сервер рассчитан на один процесс и одного владельца. OAuth flow/code находятся в памяти на 600/120 секунд; access/refresh tokens живут 1 час/7 дней. Индивидуальный отзыв, ротация refresh с историей использования, production rate limiting и постоянная БД не реализованы. Для общего сервиса нужна отдельная архитектура и проверка безопасности.
